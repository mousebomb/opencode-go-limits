# 20260929 修复 OpenCode Go 图表全空（官方改文案致三处锚点失配）+ 解析改为结构驱动

## 原始需求

"这个项目今天 OpenCode 的表又显示不出来了，排查并修复。"

## 查因结论

数据源 `anomalyco/opencode` dev 分支 `packages/web/src/content/docs/zh-cn/go.mdx` 当日改版，
`index.html` 三处**文案锚点**同时失配，实测 `parse()` 返回 `items: 0 / patterns: 0`，
图表一行都渲染不出来（不是渲染崩溃，是根本没数据）：

| # | 位置 | 旧代码期望的文案 | 官方改成了 | 后果 |
| --- | --- | --- | --- | --- |
| 1 | 价格+每月额度表 | `Token 价格按每 1M tokens 列示。` | `…按每 1M tokens 计算。` | `prices=[]` → **整图空白** |
| 2 | 官方每月请求数对照表 | `下表根据典型的 Go 使用模式提供了预估请求数：` | `…使用模式估算请求数。` | 对照列全 `—` |
| 3 | 每次请求 token 数量列表 | `- X — 每次请求 870 个输入 token，…` | `- X — 870 个输入 token，…`（删掉"每次请求"） | `patterns=0` → 全部无法估算 |

这是官方**第三次**纯靠改文案把解析打挂（前两次：`**$60**` 加粗 → `~~$15~~ **$60**` 删除线）。

同日文档另一处结构性变化：新增 **Go Plus** 套餐，价格表与官方请求数表各有两份
（`<Tabs syncKey="go-plan">` 下 Go / Go Plus 两个 TabItem），表头完全相同。

## 实现小结

放弃"多备选文案锚点"策略，改为**结构驱动**，彻底摆脱正文句子：

- 删除 `indexOfAny()` / `section()` / `parseTable(src, anchor)`。
- 新增 `parseTableByHeader(src, headers)`：全文按**表头列名**（经 `norm()` 归一，容忍空格/大小写）
  精确匹配定位表格，命中即返回数据行。文档里 Go / Go Plus 表头相同，因此取到第一份（Go）——
  这正是当前工具的目标数据集。
  - 价格表头：`模型 / 输入 / 输出 / 缓存读取 / 缓存写入 / 每月限制`
  - 官方对照表头：`模型 / 每 5 小时请求数 / 每周请求数 / 每月请求数`
  - 列名是数据契约，营销文案才会反复改，稳定性显著更高。
- `parsePatterns(src)` 改为**全文正则扫描**，不再依赖段落起止锚点；正则去掉了"每次请求"四字，
  新旧文案都能命中：
  `/^- (.+?) — ([0-9,]+) 个输入 token，([0-9,]+) 个缓存 token，([0-9,]+) 个输出 token$/gm`
- `parse()` 内两处调用改为 `parseTableByHeader`，其余（money / monthly 计算 / 渲染 / i18n / 缓存）未动。

## 验证

用「从 index.html 里切出真实解析+渲染代码，在 node 下配合 DOM stub 执行」的方式验证，
而不是另写一份逻辑（避免验证对象与线上代码不一致）：

1. **改前复现**：同一探针跑旧代码 → `items: 0 / patterns: 0`，确认根因。
2. **改后解析**：`prices` 39 行、可估算 37 个、NaN 0 个、官方对照命中 39/39、patterns 25 条。
   隐藏 2 个：`LongCat 2.5 Preview Free`、`Space Bunny Free`（价格"免费"、额度"无限制"，无法估算）。
3. **渲染实测**（DOM stub 跑真实 `render()`）：柱 37 根、柱宽 NaN 0、刻度线 3 条
   （1k / 10k / 100k，位置 13.7% / 50.3% / 87.0%，无 NaN）、明细表 37 行。
4. **端到端**：真实 fetch 两个源（均 HTTP 200 + `access-control-allow-origin: *`，内容一致）
   → 真实 `parse()` → 真实 `render()`，结果 39 档位 / 37 柱 / 0 NaN。
5. **偏离官方值的 12 行**逐行核对，全部为官方口径所致、非回归：
   - 6 行为多档位模型（`>200K` / `>256K` / `Peak`）——官方对照表只给模型汇总值，
     工具按价位档拆分估算，高档位单价成倍 → 估算约为官方值的 1/2 或 1/3。
     可复算：`Grok 4.7 (>200K)` = `$15 ÷ $0.0355 = 423` = 官方 845 的一半；
     `Qwen3.7 Plus (>256K)` = `21600 ÷ 3 ≈ 7184`。
   - 其余为官方表与文档自陈参数的固有差异（`GLM-5.3` 989 vs 1080、`Kimi K2.7 Code` 4968 vs 6750 等），
     工具值 = 文档字面参数的直接推算，可复现。此类偏差本就由页面 ▲ 标记提示。
