## Go Plus 展示方案评估（合并双柱 vs 页签切换）

用户问「两个套餐合并在一个表格里每行两根柱方便，还是切页签方便」。核实数据后的结论：

- 官方方案价：**Go $10/月、Go Plus $40/月（价格 ×4）**。
- 但额度倍数**不统一**：×2（6 行）、×3（7 行）、×4（23 行）、×8（1 行 GLM-5.3）。
  → 换算性价比 = 额度倍数 ÷ 4：`0.50x` / `0.75x` / `1.00x` / `2.00x`。
  → **只有 GLM-5.3 一个模型 Plus 更值**；13 行 Go 更值；整体合计 Plus 多 2.58 倍量但贵 4 倍，整体性价比 0.64x。
- 两张价格表 39 行、模型名与顺序**逐一相同**（已校验），唯一变量是 quota 列。
- **37 行里 17 行排序名次会变**（如 Grok 4.7：Go 第 5 → Plus 第 1）。

评估倾向：**页签切换 + 常驻「倍数 / 性价比」列**。核心理由是排序冲突无法调和（合并视图必然有一个套餐名次是错的），
且倍数只有 4 个离散值，用对数柱长表达精度反而不如一列文字（×2 的差仅占轴长 10%）；
页签方案实现成本也更低（多解析一份表 + 一个 plan 状态，不动 CSS grid 模板）。
唯一损失（不能同屏对比）用 tooltip 常驻显示两套餐数值补掉。

待用户确认后再动手实现。

## 三页整体改为手绘素描风（rough.js 手绘引擎）

用户要求"基于 roughViz 把整体风格改成手绘、画师范儿"，先问定基调，用户选**纸面素描（浅色）**。

- **关键决策：不用 roughViz 本体，改用它的底层引擎 rough.js 4.6.6**。`BarH` 有 4 条硬伤
  （只支持 `scaleLinear` 无对数刻度 / margin.left 固定 100px 长模型名溢出 / 内置 tooltip 装不下
  单价+额度+成本+对照四类信息 / 每次 new 都挂 `window resize` 监听，goat 页拖滑块会堆积）。
  dist 348 KB 大头还是不含中文的内联字体。改用 rough.js 自绘：roughViz 的斜排线观感保留，
  刻度/悬浮卡/明细表/i18n 全可控。
- **rough.js 内联进 HTML**，不走 CDN：deploy 只上传根目录 `*.html`，外部 js 传不上去；
  且离线走 localStorage 时 CDN 拉不到就是白图。每个文件 +27 KB。
- **主题唯一定义源 = `index.html`**。go-plus 由 10 处精确替换派生；goat 由拼装脚本抽取共享片段
  （CSS / 手绘滤镜 / rough.js / 绘制 helpers）再拼自己的逻辑。改主题只改 index.html。
- **本机可用手写字体（canvas 宽度比对法实测）**：霞鹜文楷、霞鹜文楷等宽、马善政楷书、
  手札体、翩翩体、行楷、娃娃体、圆体均可用；`PingFang SC` 会与 sans-serif 同宽产生假阴性。
  最终：正文/行名用霞鹜文楷，数字用霞鹜文楷等宽，标题用马善政楷书。
- **配色**：只用「墨 + 靛蓝 + 松绿」，避开紫/赤（火）与黄/棕（土）。
- **两个必踩的坑**：① `:root` 变量解析失败**不报错**，只静默让所有 `var()` 失效
  （面板透明 / 网格塌成一列 / 字体回落）——本次是拼装时多写了一个 `<style>` 标签；
  ② 轨道 `<svg>` 必须 `position:absolute`，否则显式宽度顶住网格列 `min-content`，窗口变窄不收缩。
- **验证**：`playwright-core` + ms-playwright 已缓存的 Chromium 出图 +
  功能回归（中英切换、窗口 1100→760、goat 自定义模式重算、Plus 取第二套表），全部通过，无 JS 错误。
