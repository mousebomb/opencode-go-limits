# 2026-09-29

## 修复 index.html 图表全空（OpenCode 官方文案改版致锚点失配）

- **现象**：OpenCode Go 页面打开后一行数据都没有（不是渲染崩，是 `parse()` 拿不到数据：
  `items: 0 / patterns: 0`）。
- **根因**：官方 `go.mdx` 改了 3 处正文文案 → 旧代码的文案锚点全失配：
  1. `Token 价格按每 1M tokens 列示。` → `…计算。`（价格表锚点挂 → 图空白）
  2. `…使用模式提供了预估请求数：` → `…估算请求数。`（官方对照表锚点挂）
  3. token 模式行删掉"每次请求"四字（`预估值采用以下每次请求的 token 数量` 段落仍在，但行格式变了）
- **改法（关键决策）**：放弃"多备选文案锚点"（已被打挂 3 次），改为**结构驱动**：
  - 新增 `parseTableByHeader(src, headers)` —— 按**表头列名**（`norm()` 归一后精确匹配）定位表格，
    不再认正文句子。删除 `indexOfAny()` / `section()` / `parseTable()`。
  - `parsePatterns` 改为全文正则扫描，正则去掉"每次请求"，新旧文案都命中。
  - 文档 Go / Go Plus 两套表表头相同，`parseTableByHeader` 取第一份 = Go（当前工具目标集）。
- **验证方法（可复用）**：不另写一份解析逻辑，而是从 `index.html` 切出**真实代码**
  （`常量与工具` → `主流程` 区间）+ 极简 DOM stub，在 node 下执行真实 `parse()`/`render()`。
  比浏览器 headless 验证更快，且验证对象就是线上代码。
- **踩坑**：Chrome `--headless --virtual-time-budget` 遇到挂起的网络请求会永久卡死（跑了 3 分钟不退出），
  已改用 node 端到端（真实 fetch + 真实 parse/render）。另注意 `res.text().length` 是
  **JS 字符数**不是字节数（中文 3 字节），一度误判"官方又改版了"。
- **未做**：Go Plus 套餐未纳入（官方现为 Go $10 / Go Plus 双套餐），已记在 devlog TODO。
